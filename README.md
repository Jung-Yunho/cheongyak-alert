# 청약 알림

아파트 청약(청약홈)의 **신규 공고만** 골라 텔레그램으로 보내고, 현재 열린 청약을 웹 페이지로 보여준다.

수집 대상은 두 가지다.

| 종류 | 엔드포인트 | 비고 |
|---|---|---|
| **아파트 분양** | `getAPTLttotPblancDetail` | 일반 분양 공고 |
| **무순위·잔여세대** | `getRemndrLttotPblancDetail` | 무순위 / 불법행위 재공급. **대부분 당일 접수(하루짜리)** 라 놓치기 쉽다 |
| **임의공급** | `getOPTLttotPblancDetail` | 무순위에서도 남은 물량을 선착순으로 푸는 단계. 이것도 아파트다 |

**소스마다 형식이 다르니 추가할 때 두 가지를 반드시 확인한다.**

- **날짜 형식.** 임의공급은 `20260813`, 나머지는 `2026-08-13` 이다. 안 맞추면 문자열 비교가
  조용히 뒤집혀(`"20260813" > "2026-08-12"`) **마감 판정이 통째로 무력화된다.**
  실제로 이걸 빠뜨려 임의공급이 5건 대신 152건으로 잡혔다. `iso()` 가 맞춘다.
- **금액 표기.** 임의공급의 `LTTOT_TOP_AMOUNT` 는 `"27,600"` 처럼 쉼표가 들어간다.
  숫자 검사에서 그냥 걸러져 **분양가가 조용히 전부 빠진다.** 쉼표를 떼고 본다.

같은 서비스에 오피스텔·도시형생활주택(`getUrbtyOfctlLttotPblancDetail`)과
공공지원 민간임대(`getPblPvtRentLttotPblancDetail`) 도 있지만, 주택이 아니거나 임대라
분양가 개념 자체가 없어(`SUPLY_AMOUNT`·`SUBSCRPT_REQST_AMOUNT` 로 필드가 다르다) 넣지 않았다.

외부 라이브러리 없음. JDK 11 이상이면 빌드 없이 소스 파일을 그대로 실행한다.

## 파일

| 파일 | 역할 |
|---|---|
| `Cheongyak.java` | 전부. 수집 · 필터 · 중복판정 · 전송 · 페이지 생성 |
| `run.bat` | 실행 래퍼. 작업 스케줄러에 이걸 등록한다 |
| `seen.txt` | 이미 알린 건의 키. 첫 실행 때 자동 생성 |
| `docs/index.html` | 웹 페이지. `--html` 로 생성 |
| `.github/workflows/cheongyak.yml` | GitHub Actions 스케줄 실행 |

## 설정

환경변수 4개. `setx` 로 한 번만 등록하면 된다 (등록 후 새 터미널을 열어야 반영된다).

```
setx TG_TOKEN "봇토큰"
setx TG_CHAT_ID "채팅ID"
setx APPLYHOME_KEY "data.go.kr 개인 API 인증키"
setx APT_REGIONS "서울,경기"
```

- `APPLYHOME_KEY` — 없으면 아무것도 수집하지 않는다. 필수다.
- `WEB_URL` — 메시지 맨 끝에 붙일 웹 페이지 주소. 안 정하면 링크를 안 붙인다.
  GitHub Actions 에서는 `cheongyak.yml` 에 박아뒀다.
- `APT_REGIONS` — **안 정하면 `서울,경기,인천`** (수도권). 전국을 보려면 `전국` 이라고 쓴다.
  값은 청약홈의 공급지역명과 부분 일치로 비교한다. 실제 응답 1000건 기준 지역명은 아래가 전부다.

  `경기` `서울` `부산` `인천` `충남` `울산` `경남` `대전` `강원` `광주`
  `전북` `경북` `충북` `전남` `대구` `제주` `세종`

  **`서울특별시` 가 아니라 `서울` 처럼 짧은 표기다.** 긴 이름을 넣으면 아무것도 안 걸린다.

### 텔레그램 설정

1. 텔레그램에서 [@BotFather](https://t.me/BotFather) → `/newbot` → 봇 이름과 아이디를 정한다
   (아이디는 반드시 `bot` 으로 끝나야 한다). `1234567890:AAH...` 형태의 토큰을 준다 → `TG_TOKEN`
2. **만든 봇을 찾아 들어가 START 를 누르고 아무 메시지나 보낸다.**
   텔레그램 봇은 먼저 말을 걸 수 없다. 이걸 건너뛰면
   `403 bot can't initiate conversation with a user` 가 난다. 가장 흔한 실패 원인이다.
3. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates` 를 열고
   `"chat":{"id":123456789` 의 숫자를 본다 → `TG_CHAT_ID`

### 여러 명에게 보내기

두 가지 방법이 있다. **그룹을 권한다.**

**방법 A — 그룹 (권장).** 텔레그램에서 그룹을 만들고 봇을 멤버로 초대한 뒤, 그룹에 아무 메시지나
보내고 `getUpdates` 로 그룹의 `chat.id` 를 확인한다. **그룹 ID 는 `-1001234567890` 처럼 음수다.**
그 값 하나만 `TG_CHAT_ID` 에 넣으면 된다.
사람이 늘거나 줄어도 그룹에 초대/퇴장만 하면 되고 설정은 안 건드려도 된다.

> 봇이 그룹 메시지를 못 읽어 `getUpdates` 가 비어 있으면, BotFather 에서
> `/setprivacy` → 해당 봇 → `Disable` 로 바꾼 뒤 그룹에 다시 메시지를 보낸다.
> (알림만 보낼 거라면 ID 를 확인한 뒤 다시 `Enable` 로 돌려놔도 동작한다.)

**방법 B — 개인에게 각각.** `TG_CHAT_ID` 에 쉼표로 나열한다.

```
setx TG_CHAT_ID "123456789,987654321"
```

이 경우 **각자가 봇에게 직접 START 를 눌러야 한다.** 안 누른 사람은 전송이 실패하는데,
그 사람만 건너뛰고 나머지는 정상적으로 받는다. 콘솔에 `전송 실패(건너뜀)` 으로 찍힌다.
전원 실패일 때만 `seen.txt` 를 기록하지 않고 실패로 끝내 다음 실행에서 다시 시도한다.

## 실행

```
run.bat                          평소 실행
run.bat --dry                    텔레그램 안 보내고 콘솔에만 출력
run.bat --selftest               파서 자체 점검 (네트워크 불필요)
run.bat --html docs\index.html   웹 페이지도 같이 생성
```

**첫 실행은 알림을 보내지 않는다.** 현재 목록을 기준선으로 `seen.txt` 에
등록만 한다. 두 번째 실행부터 그 이후 새로 뜬 건만 나간다. 처음부터 다시 받고 싶으면
`seen.txt` 를 지우면 된다.

작업 스케줄러에는 `run.bat` 을 등록한다. 하루 2회 정도면 충분하다.
**아래 GitHub Actions 로 돌리면 작업 스케줄러는 필요 없다** (PC 를 안 켜도 동작한다).

## 웹으로 보기 (GitHub Actions + Pages)

수집을 GitHub 이 대신 돌리고, 만들어진 정적 HTML 을 Pages 가 서빙한다.
브라우저가 API 를 직접 부르지 않으므로 **CORS 도 없고 인증키도 노출되지 않는다.**

```
Actions (cron) ── Cheongyak.java ── 텔레그램 전송
                                 └─ docs/index.html 생성 → commit → Pages 서빙
```

### 설정 순서

1. **public 저장소를 새로 만들고** 이 폴더 전체를 push 한다.
   (무료 Pages 는 public 저장소여야 한다. 전용 저장소를 권한다 — Actions 가 하루 2회
   결과를 커밋하므로 다른 프로젝트와 섞으면 이력이 지저분해진다.)
2. **Settings → Secrets and variables → Actions**
   - `Secrets` 탭: `TG_TOKEN`, `TG_CHAT_ID`, `APPLYHOME_KEY`
   - `Variables` 탭: `APT_REGIONS` — **안 만들면 `서울,경기,인천`** 이 기본이다.
     다른 지역을 보고 싶을 때만 만든다 (전국이면 값을 `전국` 으로).
3. **Settings → Pages** → Source: `Deploy from a branch` → Branch: `main` / 폴더 `/docs`
4. **Actions 탭 → 청약 알림 → Run workflow** 로 한 번 수동 실행해 확인한다.
5. 주소는 `https://<사용자명>.github.io/<저장소명>/` 이다.

실행 시각은 `cheongyak.yml` 의 `cron` 이다. GitHub 은 UTC 를 쓰므로
`'0 0,9 * * *'` 는 KST 09:00 / 18:00 이다. 예약 실행은 러너가 붐비면 수십 분 밀릴 수 있다.

### 실패하면 어떻게 되나

**그룹이 슈퍼그룹으로 전환되면 `chat_id` 가 바뀐다.** 인원이 200명을 넘을 때만이 아니라
공개 링크 설정·관리자 권한 변경 같은 것으로도 전환된다. 실제로 겪었다.
텔레그램이 응답에 새 ID(`migrate_to_chat_id`)를 담아 주므로 **그 ID 로 한 번 다시 보내고**
로그에 "TG_CHAT_ID 를 … 로 바꾸세요" 를 남긴다. 알림은 안 끊기지만, Secret 을 고칠 때까지
매번 이 경로를 타므로 로그를 보면 바로 고칠 수 있다.

수집이 0건이면 멀쩡한 페이지를 빈 페이지로 덮지 않고 **실패로 종료한다.**
그러면 Actions 가 실패 알림 메일을 보낸다.
분양가 조회만 실패한 경우는 그 줄만 빠지고 나머지는 정상 발송된다.

`seen.txt` 도 같이 커밋된다. 이게 "이미 알린 건" 기록이라, 저장소에서 지우면
다음 실행이 첫 실행으로 취급되어 기준선만 다시 잡는다(알림은 안 나간다).

## 텔레그램과 웹 페이지의 역할이 다르다

- **텔레그램** — 이전에 안 알린 **신규 건만** 보낸다. 같은 건을 다시 보내지 않는다.
- **웹 페이지** — 매 실행마다 **지금 열려 있는 전부**를 다시 그린다. 지난 메시지를 뒤질
  필요 없이, 메시지 맨 아래 링크로 현재 현황을 본다.

### 지역 필터 (웹 전용)

목록 위의 드롭다운 두 개로 `서울 > 마포구` 처럼 좁혀 볼 수 있다.
정적 페이지라 브라우저에서 보이고 숨기는 방식이고, 목록은 그날 실린 카드에서 만들어
빈 항목이 안 생긴다. **알림에는 적용되지 않는다** — 잘못 좁히면 놓치기 때문에
텔레그램은 `APT_REGIONS`(시·도 단위) 그대로 둔다.

**시·도가 바뀌면 시·군·구는 항상 초기화되고, 시·도가 "전체"면 시·군·구 상자는 숨는다.**
"시·도 없이 구만 선택된" 상태를 만들 수 없게 하려는 것이다. 그 상태를 허용하면
`중구`처럼 여러 시·도에 같은 이름이 있는 경우 서울 중구와 인천 중구가 섞여 나온다
(실제 응답 1000건 기준: `중구`=서울·인천, `강서구`=서울·부산, `동구`/`서구`=인천 외 다수).
숨기기만 하고 값을 안 지우면 보이지 않는 필터가 계속 걸리므로 둘은 세트다.

시·군·구는 API 에 필드가 없어 공급 주소를 잘라 쓴다(`gugunOf`). 그래서:

- **경기 특례시는 시까지만.** `경기도 성남시 수정구 …` → `성남시`.
  `서울 > 마포구` 는 2단계인데 `경기 > 성남시 > 수정구` 는 3단계라 깊이가 안 맞는다.
- **주소에서 못 읽은 건은 어떤 구를 골라도 숨기지 않는다.** 잘못 숨겨 놓치는 쪽이 더 위험하다.
  시·도는 별도 필드라 정확하므로 시·도 선택에서는 정상적으로 걸러진다.

### 지도 (웹 전용)

카드의 주소를 누르면 네이버 지도 검색으로 열린다. **지도를 직접 그리지 않는 이유**는 API 에
좌표가 없기 때문이다(위경도 필드가 아예 없다). 지도를 얹으려면 주소→좌표 지오코딩이
필요하고, 그건 API 키가 하나 더 붙고 캐시까지 관리해야 한다. 링크면 그 비용 없이 목적을 채운다.

**공급 주소는 도로명이 아니다.** 수도권 231건 기준으로 도로명 형태는 16% 뿐이고,
`"일원"` 43% · 괄호 34% · 번지 없음 30% · 블록 표기 24% 다. 그대로 검색에 넘기면 잘 못 찾아서
`mapQuery` 가 다듬는다.

| 원문 | 검색어 |
|---|---|
| `서울특별시 송파구 거여동 181, 202번지 일원` | `서울특별시 송파구 거여동 181번지` |
| `인천광역시 검단구 검단신도시 AB23BL(인천광역시 검단구 마전동 산175-7번지 일원)` | `인천광역시 검단구 마전동 산175-7번지` |
| `경기도 오산시 오산세교2지구 A-13블록 호반써밋(경기도 오산시 초평중앙로 65)` | `경기도 오산시 초평중앙로 65` |
| `경기도 광주시 초월읍 도곡길 27(쌍동리 402)` | `경기도 광주시 초월읍 도곡길 27` |

**번지가 없는 건은 블록 코드가 검색을 통째로 실패시킨다.** `D1-1BL` 같은 표기는 지도에
없어서, 그대로 넘기면 결과가 0건이 되고 카카오맵이 직전에 보던 엉뚱한 위치를 띄운다.
블록 코드만 떼면 남는 지구·단지명으로 정확히 찾힌다.

| 원문 | 검색어 |
|---|---|
| `…원삼면 용인 반도체 클러스터 일반산업단지 D1-1BL` | `…원삼면 용인 반도체 클러스터 일반산업단지` |
| `…거모동, 군자동 시흥거모 공공주택지구 내 A-5블록` | `…거모동, 군자동 시흥거모 공공주택지구` |

**번지·도로명이 없으면 행정구역까지만 남긴다.**

| 원문 | 검색어 |
|---|---|
| `…원삼면 용인 반도체 클러스터 일반산업단지 D1-1BL` | `경기도 용인시 처인구 원삼면` |
| `…거모동, 군자동 시흥거모 공공주택지구 내 A-5블록` | `경기도 시흥시 거모동` |

지구·단지명을 살려두면 **지도 제공자에 따라 결과가 갈린다.** 카카오는 "시흥거모
공공주택지구"를 장소로 갖고 있어 잘 찾았지만, 네이버는 없어서 "조건에 맞는 업체가
없습니다" 가 뜨고 엉뚱한 위치(강남 역삼동)를 보여줬다. 행정구역은 어느 지도에나 있으니
정확도를 조금 내주고 안정성을 택했다 — **틀린 위치를 보여주는 게 제일 나쁘다.**
단지 위치는 카드의 청약홈 공고 링크에서 확인하면 된다.

**주소가 쿼리스트링이 아니라 경로에 들어간다**(`/p/search/<검색어>`). 경로에서 `+` 는
공백이 아니라 문자 그대로라, `URLEncoder` 가 만드는 `+` 를 `%20` 으로 바꿔야 한다.
카카오(`?q=`)에서 그대로 옮기면 여기서 조용히 틀린다. `/v5/search/` 는 302 로 넘어가므로
`/p/search/` 를 쓴다.

정확한 위치는 카드의 청약홈 공고 링크에서도 확인된다 —
**링크가 어긋나도 조용히 사라지지 않는 게 지오코딩 대비 장점이다.**

### 상태 구분

마감이 지난 건은 아예 싣지 않고, 남은 것을 급한 순으로 정렬한다.

텔레그램 메시지와 웹 페이지가 같은 배지·같은 순서를 쓴다.

| 배지 | 뜻 | 정렬 |
|---|---|---|
| 🔴 **오늘 마감** / **내일 마감** | 접수 중이고 마감이 코앞 | 맨 위 |
| 🟢 **접수중** | 접수 기간 안 | 마감 임박한 순 |
| 🟠 **예정** | 아직 시작 전 | 빨리 시작하는 순 |

### 페이지 구성

- 상단 **요약 칩**은 **눌러서 그 상태만 볼 수 있다.** 지역 필터와 AND 로 걸리고,
  같은 칩을 다시 누르면 해제된다. 칩의 숫자는 **지금 지역 선택 안에서** 몇 건인지를 보여준다 —
  서울만 골랐는데 칩이 전체 건수를 그대로 두면 앞뒤가 안 맞는다.
  0건인 상태는 눌러도 빈 화면만 나오므로 비활성으로 막는다.
- 카드에서 **분양가와 공급규모만 따로 크게** 뺐다. 값을 판단할 때 제일 먼저 보는 정보인데
  본문 줄과 섞어두면 눈에 안 들어온다. `Item` 이 `price`/`units` 를 따로 들고 있는 이유다.
- 상태는 카드 **왼쪽 세로선 색**으로도 표시한다. 배지를 안 읽어도 훑어보면 구분된다.
- 필터는 **sticky** 라 스크롤해도 따라온다. 넓은 화면(760px+)에서는 2열이 된다.
- 색은 CSS 변수 두 벌(라이트/다크)로만 관리한다. 카드마다 색을 흩어놓으면 톤을 바꿀 때
  전부 뒤져야 한다. `prefers-color-scheme` 으로 자동 전환된다.
- **주소는 📍 와 점선 밑줄**로 링크임을 표시한다. 그냥 글로 보고 지나치기 쉬워서다.
  마우스를 올리면 실선으로 바뀌고 "네이버 지도에서 보기" 툴팁이 뜬다.
- 외부 CSS·폰트·JS 를 안 쓴다. 파일 하나로 끝나는 게 이 프로젝트의 전제라 그대로 지켰다.

## 알아둘 것

- **`run.bat` 은 ASCII 로만 유지한다.** `chcp` 가 콘솔 코드페이지를 파일 중간에서 바꾸는데,
  cmd.exe 는 배치 파일을 바이트 오프셋으로 다시 읽기 때문에 위쪽에 한글이 있으면
  파싱이 어긋나 주석을 명령으로 실행해 버린다. 한글 설명은 이 README 에 둔다.
- **`-Dfile.encoding=UTF-8` 을 빼면 안 된다.** JDK 17 은 한국어 Windows 에서 기본 charset 이
  MS949 라, 단일 파일 런처가 UTF-8 로 저장된 소스를 MS949 로 읽어 한글 리터럴을 전부
  깨뜨린다. 그러면 지역 필터가 아무것도 못 걸러 **에러 없이 조용히 0건**이 된다. JDK 18 부터는
  기본이 UTF-8 이라 없어도 되지만 있어도 무해하다.
- **`HttpURLConnection` 을 쓴다.** 요즘 API 인 `java.net.http.HttpClient` 는 내부에서 NIO
  Selector 용 loopback 파이프를 여는데, 사내 보안 정책으로 그게 막힌 PC 에서는
  `Unable to establish loopback connection` 으로 아예 뜨지 않는다. 실제로 이 PC 가 그렇다.
- **JSON 을 정규식으로 읽는다.** JDK 에 파서가 없고, 라이브러리를 넣으면 "파일 하나로 실행"
  이라는 장점이 사라진다. 청약홈 응답이 중첩 없는 평면 구조라 가능하다(실제 응답 200건 확인).
  구조가 바뀌면 0건으로 나타나므로 로그에 드러난다.
- **접수일 필드명이 엔드포인트마다 다르다.** 아파트 분양은 `RCEPT_*`, 무순위는
  `SUBSCRPT_RCEPT_*` 를 쓰고, 드물게 `GNRL_RCEPT_*` 만 채워진 건도 있다(실제 60건 중 2건).
  `first()` 로 순서대로 찾는다. 나머지 필드는 두 소스가 같아서 파서 하나로 처리된다.
- **접수 마감이 지난 건은 제외한다.** 종료일을 못 읽으면 버리지 않고 남긴다 —
  잘못 버려서 놓치는 쪽이 더 위험하다.
- **`seen.txt` 키에 소스별 접두어(`apt:` / `rem:`)를 붙인다.** 두 데이터셋의 공고번호가
  겹쳐도 서로를 덮지 않게 하려는 것이다.
- 공고일 최신순 200건만 조회한다.
- **분양가는 별도 엔드포인트에서 온다.** 분양정보(`getAPTLttotPblancDetail`)에는 금액 필드가
  없고, 주택형별 상세(`getAPTLttotPblancMdl`)의 `LTTOT_TOP_AMOUNT`(단위: 만원)에 있다.
  공고마다 따로 호출해야 해서, 지역·마감 필터를 통과한 것만 추려 그만큼만 부른다.
  - 주택형마다 값이 달라 **최저~최고 범위**로 보여준다. 펜트하우스가 있으면 범위가 크게
    벌어진다(김포 한강 푸르지오: 84㎡ 7.4억 ~ 180㎡ 30.0억). 잘못된 값이 아니다.
  - 억으로 반올림해 같아지면 하나만 쓴다(44,812 / 44,555 만원 → `4.5억`).
  - **금액 조회가 실패해도 그 줄만 빠지고 알림은 정상 발송된다.** 임대처럼 분양가가 없는
    유형도 마찬가지로 그냥 줄이 빠진다.

## 자체 점검

`run.bat --selftest` 는 네트워크 없이 파서만 검사한다. 지역 필터, 마감 필터, 상태 배지와
정렬, 시·군·구 추출, 분양가 표기, 메시지 분할, null 처리, JSON 이스케이프 양방향을 확인한다.
파서를 손댔으면 이걸 먼저 돌린다.
